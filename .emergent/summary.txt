<analysis>**original_problem_statement:**
The user is building a comprehensive web application for a modified Lord of the Rings 5e tabletop role-playing game.

**Initial Core Requirements:**
*   A detailed character creator with PDF export.
*   A full user authentication system (Maestro, Admin, Player).
*   Game data management (rules, items, locations).
*   An interactive map of Middle-earth.

**New Requirements Added During Project:**
*   **Enhanced Travel System:** A complete, rule-driven travel generator that calculates routes using A* pathfinding.
*   **Dynamic Event Generation:** Events are no longer pre-calculated. Instead, their occurrence is determined by a Guide's Orientation skill check after each event is resolved. The result of the roll determines the distance to the next event. The journey concludes when a roll result equals or exceeds the remaining distance to the destination.
*   **Journey Stages & Fatigue:** Long journeys are to be broken into 7-10 day stages. A Fatigue check is made at the end of each stage. Resting at safe havens (like Rivendel) resets fatigue accumulation.
*   **Resource Management:** The system must track and display the required food and water for a journey based on its duration and party size. The UI should display the effects of exhaustion levels.
*   **AI-Powered Narratives:** Travel event outcomes and journey summaries should be enriched with dynamically generated story text. The tone should be natural and mythological, not epic or a dictionary, and should not mention game mechanics like PX. The narrative should be aware of the journey's progress (e.g., leaving the Shire vs. approaching the Misty Mountains).
*   **Printable Journey Chronicle:** Users must be able to export a stylized, Tolkien-themed PDF of their journey. This PDF must include a visually appealing map of the route taken, with event locations marked (green for success, red for failure).
*   **Interactive Map Editors:**
    *   **Terrain Editor:** A tool for the user to paint terrain difficulty (Easy, Moderate, Hard, etc.) and land type (Wild, Free, etc.) directly onto a map, which will then be used by the pathfinding algorithm.
    *   **Path Debugger:** An interactive tool where the user can define a path step-by-step (e.g., every 10km) to teach the agent the correct routes.
*   **Journey Debugging:** A feature to export the entire state of a calculated journey (path, events, decisions, etc.) into a JSON file for easy debugging.
